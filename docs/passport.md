# Паспорт проекта

## 1. Название проекта

Магазин обуви "Кукбаш"

## 2. Проблема

Учёт товара в магазине ведут в тетради и Excel: продавец не видит, какой размер закончился, а покупатель не может заранее узнать, есть ли нужная пара. Из-за этого часть клиентов уходит без покупки.

## 3. Пользователи

покупатель — ищет обувь по размеру и модели, оформляет заказ; продавец — добавляет товар, отмечает продажи и обновляет остатки; администратор — заводит сотрудников и раздаёт права доступа.

## 4. Цель проекта

Сделать так, чтобы покупатель находил нужную пару и оформлял заказ онлайн, а продавец видел актуальные остатки по каждому размеру.

## 5. Метрики успеха

поиск пары по размеру и модели — < 1 минуты; оформление заказа — < 2 минут; остаток по размеру уменьшается сразу после подтверждения продажи, без ручного ввода; продавец добавляет новую модель в каталог — < 3 минут.

## 6. Границы (что НЕ делаем)

реальные платёжные системы не подключаем — оплата учебным симулятором; мобильного приложения нет, только десктопная версия; доставку курьером не моделируем, заказ забирают в магазине;отзывы и рейтинги товаров не реализуем.

## 7. Риски

не успеем сделать поиск с фильтрами к дедлайну → сначала каталог и заказ, поиск во вторую очередь; nсложно набрать 30+ моделей обуви → берём реальный ассортимент из открытых каталогов; команда может разойтись в схеме БД → фиксируем структуру таблиц на паре 3–4 и дальше не меняем; продавец и администратор могут получить одинаковые права → разграничиваем роли сразу при проектировании.
